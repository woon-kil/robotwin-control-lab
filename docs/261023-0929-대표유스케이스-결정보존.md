## 보존하는 결정

최종 대표 데모로 `Hazardous Filter Handling`을 직접 구현하지 않는다.

대표 Use Case는 다음으로 좁힌다.

**Generic Industrial Bolt Fastening / Loosening with Torque-Aware Validation**

위험/원격 산업환경에서 Long-Reach Manipulator가 수행하는 볼트 체결·해체 작업을 Digital Twin에서 사전 검증하고, 검증된 작업만 Controller 계층으로 전달하며, 실행 단계에서는 Torque/Angle Feedback으로 작업 결과를 판정하는 방향이다.

본 프로젝트는 특정 회사 제품의 복제품이 아니다. 다음을 주장하지 않는다.

- 실제 FilterBot 구조, 작업 순서, End-Effector, DH, 체결 Torque, 제어 알고리즘의 복제
- 실제 PMAC proprietary protocol 복제

구현 대상은 공개적으로 확인 가능한 산업용 원격 유지보수/볼트 작업 도메인을 참고한 Generic Industrial Maintenance Workcell이다. 이 문서는 그 workcell을 구현하지 않는다.

## P-001A.1에 반영한 방향

대표 Task 후보는 `BOLT_FASTEN`, `BOLT_LOOSEN`이다.

개념 흐름:

```text
Task Selection
→ Bolt Target Pose
→ Bolt Tool TCP
→ Approach
→ Alignment
→ Pre-Execution Validation
→ SAFE TO ATTEMPT / REJECT
→ Operator Approval
→ Controller Execution
→ Engage
→ Rotate
→ Torque / Angle Feedback
→ FASTENED / LOOSENED / FAILED
→ Retract
→ Target vs Actual Comparison
→ Evidence
```

Pre-Execution Validation의 PASS는 `SAFE TO ATTEMPT`다. 체결 성공이 아니다. 이후 검증 후보: Reachability, IK feasibility, Joint limits, Robot collision, Bolt Tool collision, Safety zone, Tool TCP alignment, Approach trajectory, Task / Tool compatibility. 필수 항목이 모두 PASS해야 Controller 실행을 승인할 수 있다는 방향이다. required 목록은 이 문서가 잠그지 않는다.

Execution 결과 후보는 `FASTENED`, `LOOSENED`, `FAILED`, `FAULT`다. 개념 입력 후보는 Rotation Angle, Rotation Speed, Torque Feedback, Contact State, Tool State, Controller State다.

초기 Torque는 Virtual Fastening Process와 Virtual Torque Sensor로 둔다. 실제 industrial bolt tool이나 Force/Torque Sensor 보유를 전제하지 않는다. HMI와 Evidence에는 simulated/virtual임을 식별한다. 실제 측정값처럼 표현하지 않는다.

실제 대상 제품의 체결 Torque는 추정하지 않는다. 시험에 숫자가 필요하면 `PROJECT TEST PARAMETER` 또는 `SIMULATION TEST PARAMETER`로 정의하고, FilterBot이나 실제 산업설비 사양이 아님을 적는다. 이 문서는 Torque 숫자를 만들지 않는다.

이후 Fastening Evidence 후보: Target Torque, Peak Torque, Final Torque, Rotation Angle, Torque-Angle history, Completion state, Fault state, Timestamp. 구현 Gate 전에는 값을 생성하지 않고 PASS를 만들지 않는다.

대표 Tool은 Bolt Fastening / Loosening Tool 하나다. Cover Handling, Filter Gripper, Filter Transport, Inspection, Automatic Tool Changer는 현재 MVP에서 제외한다. Tool 확장은 이후 architecture에서 가능할 수 있으나 지금 여러 Tool을 구현하지 않는다.

Bolt Tool은 Robot Flange와 별도의 TCP를 둔다. 개념은 Robot Flange → Bolt Tool → Bolt Tool TCP다. Tool 길이, 자세, 충돌 geometry는 이후 FK, IK target, Collision, Reachability, Approach, Alignment에 반영할 후보이다. P-001A와 이 문서에서는 구현하지 않는다.

대표 정상 시나리오 후보: 사용자가 `BOLT_FASTEN` 또는 `BOLT_LOOSEN`을 고르고 SIMULATE하면 Reachability, IK, Joint Limit, Tool Collision, Safety Zone, Tool TCP Alignment, Trajectory가 PASS이고 결과가 `SAFE TO ATTEMPT`인 뒤, `APPROVE & EXECUTE`로 Approach, Align, Engage, Rotate, Virtual Torque/Angle, Completion, Retract, Evidence까지 가는 흐름이다.

대표 실패 시나리오 후보: 접근 경로에 장애물이 있으면 Tool Collision FAIL, 결과 `REJECT`, Controller execution `BLOCKED`다.

이후 README, HMI, Portfolio에 쓸 의미는 다음이다. 산업용 로봇의 볼트 체결·해체 작업을 실제 Controller에 보내기 전에 Digital Twin에서 사전 검증하고, 안전하게 시도 가능한 작업만 승인·실행하며, 실행 중 Torque/Angle Feedback으로 작업 결과를 검증하는 Robot Control Validation Platform. 이 문장은 아직 README에 넣지 않는다.
